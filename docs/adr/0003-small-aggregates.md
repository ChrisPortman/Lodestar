# Small aggregates, with cross-aggregate rules in application services

The domain has six aggregates, each with its own version used for optimistic locking: **Person**, **Project** (name, Project Code, description, archived flag, Project Leader, Members, Health Rating), **Action**, **Risk**, **Blocker** and **Comment** (added for #40; it refers to its Project and its target by ID, so commenting never bumps the target's version). Items refer to their Project by ID. We rejected one Project aggregate holding every item, because then any two edits made during the same meeting would conflict. Rules that span aggregates (only Members can be assigned; removing a Member unassigns their open items, with each unassignment bumping that item's version and writing its own Change History entry; Blocker links stay within one Project; an archived Project is entirely read-only) are enforced by application services inside a single database transaction.
